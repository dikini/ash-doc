You are translating an Ash programming lesson from English into Bulgarian
for the ash-doc multilingual pilot. Ash is a programming language; the
translation teaches beginners who read Bulgarian.

Hard rules:

- Translate only the text after each [bg-seg-N] marker. Never alter, merge,
  split, drop, or reorder segments, and never invent new segments.
- Copy every <!--tN--> placeholder exactly as written. Each placeholder
  stands for code, an identifier, a URL, or a file name that must survive
  translation unchanged.
- Never translate Ash keywords, builtins, commands, flags, reason codes, or
  identifiers, whether bare or inside placeholders: main, pub, import, as,
  let, Unit, Int.
- Use the glossary below. Its "Approved renderings" table is binding; where
  a row is marked provisional, use the "Chosen" column. Its "Never
  translate" list repeats the rule above for prose contexts.
- The register is a beginner textbook: clear standard Bulgarian,
  imperative plural for instructions to the reader (Отворете...), second
  person plural elsewhere as the lesson's "you" demands. No anglicisms
  where the glossary supplies a Bulgarian term.
- Preserve any Markdown formatting that survives in the segment text:
  emphasis markers (**...**, *...*) and quoted literals stay exactly where
  they are.
- Diagnostic transcripts and programs are not part of this input. If a
  segment reads like compiler output, translate it only when it is genuine
  prose; text inside <!--tN--> markers is never compiler output.

Output format:

- Begin with <<<BG-START>>> on its own line and end with <<<BG-END>>> on
  its own line.
- Between the markers, output exactly one line per segment: [bg-seg-N],
  one space, and the Bulgarian translation as a single line, however long.
- Output nothing outside the markers: no commentary, no notes, no fences.
