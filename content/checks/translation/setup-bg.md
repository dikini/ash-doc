# Настройка на четеца

## Подготовка на Ash {#prepare-ash}

Учебният път използва командния инструмент `ash`. Трябват ви Git и Rust
toolchain с Cargo. Клонирайте Ash с неговия Git URL, изберете точния
commit за това издание и го компилирайте:

```text
git clone git@github.com:dikini/ash-lang.git
cd ash-lang
git switch --detach 354c76b391fe4af665cf6a03479a9874a57cb3e3
cargo build --locked
```

Изпълнимият файл вече е `target/debug/ash`. Направете по-късото име `ash`
налично в текущия терминал:

```text
export PATH="$PWD/target/debug:$PATH"
export ASH_LIBRARIES="$PWD/libraries"
export ASH_NATIVE_CACHE="$PWD/target/ash-doc-native"
```

Дръжте този терминал отворен, докато работите по учебния път.
`ASH_LIBRARIES` избира библиотеките на същия checkout. Урокът за буферите
го използва с `--root ffi="$ASH_LIBRARIES"`; обикновените уроци не
изискват опция за root. `ASH_NATIVE_CACHE` позволява на последователните
native компилации да използват повторно зависимостите си. Native
компилациите на буфери изискват Linux x86-64 GNU, съответстващия Rust
toolchain, кеширани Cargo зависимости и native linker. Техните
генерирани изпълними файлове отпечатват стойност без интерпретаторския
суфикс `: Type`.

## Четене на диагностика {#read-a-diagnostic}

Когато урок покаже отхвърлена програма, транскрипцията включва командата
и пълното съобщение на английски. Водещият `$` отбелязва prompt на
обвивката; не го пишете. `--message-format human --locale en` избира
изрично това представяне. Този компилатор извежда обикновен текст без
цветове на терминала; няма опция за цвят, която да се настройва.

Ash отпечатва канонични абсолютни пътища към източниците. В показаните
съобщения е заменен само префиксът на checkout с
`/path/to/ash-doc/`. Вашият терминал ще покаже реалното местоположение
на вашия checkout. Останалата част от всеки път, извадката от източника,
етикетите и съобщението са непроменени. Съобщенията на компилатора са
на английски по договора на инструмента; преводът ги запазва такива.

Прочетете обяснението първо, после проследете етикетите към източника
обратно към програмата. Редът `reason:` дава вторичен идентификатор на
вида на грешката; той не замества обяснението. Тези отхвърляния на
източника пишат съобщенията си на стандартния изход за грешки,
оставят стандартния изход празен и завършват със статус `1`.
