# Програма на Ash

Често си представяме програмата като списък от команди: направете това, после
направете онова. Изходният файл на Ash има друга структура. Той съдържа
дефиниции. Те описват изрази, а изразите изчисляват стойности.

За да може една програма на Ash да се стартира, трябва да има място, от което
да започне. В Ash това е дефиниция с име `main`. Когато подадете изходен файл
на `ash`, той изчислява `main ()` и отчита получената стойност и нейния тип. В
първата ни програма изчислението е достатъчно кратко, за да го видим цялото.

Отворете текстов редактор, въведете тези два реда и ги запазете като
`program.ash`:

<!-- source: src/01-literal.ash -->
```ash
main : Unit -> Int
main () = 42
```

Вторият ред дефинира изчислението: дясната му страна е цялото число `42`.
Първият ред е неговата *сигнатура*. Прочетете `Unit -> Int` като „приема
стойност от тип `Unit` и произвежда стойност от тип `Int`“. `Unit`, *unit
типът*, има една стойност, записана като `()`; `Int` е типът на целочислените
стойности.

Предскажете стойността, която произвежда `main ()`, после стартирайте файла от
терминала:

```text
ash program.ash
```

Ash отчита:

```text
42 : Int
```

Резултатът потвърждава обещаното от двата реда. Дясната страна на `main` е
*израз*, а изчисляването му произвежда отчетената стойност; сигнатурата задава
типа.

Тъй като `main` приема `()`, не му е нужен вход, за да изчисли резултата си.
[Правилата за начална точка][entry] изискват тази начална дефиниция да се
намира във файла, избран за изпълнение.

## Изразите изчисляват стойности

В първия ни израз нямаше нищо за изчисляване: `42` вече е стойност. Един израз
може също да съчетава стойности с операция. Да предположим, че все още искаме
`42`, но този път да го получим чрез събиране. Променете програмата така:

<!-- source: src/02-addition.ash -->
```ash
main : Unit -> Int
main () = 40 + 2
```

Дясната страна на `main` вече е изразът `40 + 2`. Преди да стартирате файла,
изчислете стойността му. Същата команда вече отчита:

```text
ash program.ash
42 : Int
```

И двете програми произвеждат една и съща стойност. В първата изразът вече е
`42`. Във втората Ash изчислява събиране, за да получи `42`.

Изразите могат да съдържат по-малки изрази. Помислете какво трябва да се
случи, когато заедно се срещнат две различни аритметични операции:

<!-- source: src/03-precedence.ash -->
```ash
main : Unit -> Int
main () = 1 + 2 * 3
```

Умножението се групира по-тясно от събирането. Използвайте това правило, за да
предскажете стойността преди стартиране. Ash отчита `7 : Int`; сравнете с тези
стъпки:

```text
1 + 2 * 3
1 + 6
7
```

По-малкото умножение произвежда `6`; след това събирането използва тази
стойност, за да произведе `7`.

Да предположим, че искаме първо да се извърши събирането. Скобите ни
позволяват да зададем това групиране в самия израз:

<!-- source: src/04-grouping.ash -->
```ash
main : Unit -> Int
main () = (1 + 2) * 3
```

Променило се е само групирането. Предскажете стойността, после стартирайте
файла. Ash отчита `9 : Int`. Изчислението вече протича така:

```text
(1 + 2) * 3
3 * 3
9
```

Скобите превръщат `1 + 2` в по-малкия израз, който Ash изчислява първо.

> **С учебен асистент:** Стартирайте и двете програми с различно групиране.
> Покажете на асистента предвижданията си, двете програми и действителните
> резултати от `ash`. Обяснете сами разликата, после помолете асистента да
> проверява обяснението ви, като ви задава въпроси стъпка по стъпка.

Досега `main` съдържаше цялото изчисление. Дори вложените примери се побираха
на един ред. Когато изчислението нарасне, ни трябва начин да дадем име на
полезна част от него и да я използваме в друг израз.

## Даване на име на изчисление

Следващата програма дава име на изчисление — `increment`. То прибавя единица
към цяло число:

<!-- source: src/05-function-call.ash -->
```ash
increment : Int -> Int
increment number = number + 1

main : Unit -> Int
main () = increment 41
```

Първите два реда образуват едно цяло. Сигнатурата `Int -> Int` казва, че
`increment` приема цяло число и произвежда цяло число. В дефиницията `number`
е *параметър*: той представлява всеки вход, който `increment` получава.
Изразът `number + 1` описва как се изчислява резултатът.

Последният ред използва израза `increment 41`. Това е *извикване на функция*,
а `41` е неговият *аргумент*. За да разберете извикването, използвайте `41`
навсякъде, където дефиницията използва параметъра си. Това заместване на
параметър с аргумент се нарича *заместване*. Предскажете резултата преди
стартиране:

```text
ash program.ash
42 : Int
```

Заместването обяснява този резултат:

```text
increment 41
41 + 1
42
```

Аргументът замества параметъра със стойността `41`, така че и събирането, и
съдържащото го `main` произвеждат `42`.

Щом дадем име на изчисление, можем да го включим в друго изчисление. Добавете
функция, която удвоява цяло число, после използвайте двете функции в `main`:

<!-- source: src/06-composition.ash -->
```ash
increment : Int -> Int
increment number = number + 1

double : Int -> Int
double number = number * 2

main : Unit -> Int
main () = double (increment 20)
```

Скобите запазват `increment 20` като аргумент на `double`. Започнете с
вътрешното извикване и продължете навън, за да предскажете резултата.
Стартирането на програмата отчита `42 : Int`, както показва проследяването:

```text
double (increment 20)
double 21
21 * 2
42
```

Тук резултатът от `increment` става вход за `double`. Свързването на функции
по този начин се нарича *композиция на функции*.

## Откъде започва изчисляването?

Последният ни изходен файл съдържа три дефиниции, но Ash започва с `main`.
Само случайно ли избрахме името `main`? Можем да проверим, като дадем друго
име на същия вид изчисление:

<!-- source: src/07-missing-main.ash -->
```ash
answer : Unit -> Int
answer () = 42
```

Коя дефиниция в този файл би могла да осигури необходимото извикване на `main
()`? Стартирайте запазения пример с `content/learn`, за да проверите това
изискване за началната точка:

<!-- diagnostic: src/07-missing-main.ash -->
<!-- markdownlint-disable MD013 -->
```text
$ ash --message-format human --locale en what-is-an-ash-program/src/07-missing-main.ash
The entry module must define its own `main`; importing one is not enough.
  --> /path/to/ash-doc/content/learn/what-is-an-ash-program/src/07-missing-main.ash:1:1
1 | answer : Unit -> Int
  | ^ This is the entry module.
2 | answer () = 42
  | ^ This is the entry module.
reason: entry.missing-main
```
<!-- markdownlint-enable MD013 -->

Първото изречение посочва какво липсва: началният модул трябва да дефинира
свой собствен `main`. Етикетите на изходния код обхващат дефиницията `answer`
в този файл и го посочват като начален модул. В тези редове няма нищо с име
`main`. В изречението се споменават и импортите; ще се запознаем с тях в
следващата глава. За тази програма от един файл преименувайте и двете срещания
на `answer` на `main`, за да дадете на Ash началната дефиниция.

Дефиницията на `answer` описва изчисление, но Ash не отгатва коя дефиниция
трябва да стартира програмата. Той търси `main` и започва с изчисляването на
`main ()`. Затова във всяка работеща програма в урока присъства това име.

го запазете като `program.ash`. После съставете друга двойка функции:

1. Дефинирайте `square : Int -> Int`, която умножава входа си сам по себе си,
   и я извикайте от `main` като `double (square 3)`.

   резултата.
3. Стартирайте програмата и сравнете резултата с изчислението си.

> обясните собственото си.

## Цялата програма

Сега можем да отговорим на въпроса от заглавието. В най-простия си вид
програмата на Ash е един изходен файл с дефиниции, включително една с име
`main`, от която започва изчисляването. Дефиницията дава име на изчисление.
Изразът отдясно определя стойността, която то произвежда, а извикванията на
функции позволяват на едно изчисление да използва стойност, произведена от
друго.

Когато стартирате файла, Ash изчислява `main ()` и отчита получената стойност
и тип. Всяка програма тук се побира в един изходен файл, но програмите на Ash
могат да съдържат и повече файлове. Следващият въпрос е как да използвате
дефиниция от един файл в друг.
