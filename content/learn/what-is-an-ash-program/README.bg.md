# Програма на Ash

Често си представяме програмата като списък от команди: направете това, после
направете онова. Изходният файл на Ash има друга структура. Той съдържа
дефиниции. Те описват изрази, а изразите изчисляват стойности.

За да може една програма на Ash да се стартира, тя трябва да има и място, от
което да започне. Ash използва дефиниция с име `main`. Когато подадете
изходен файл на `ash`, то изчислява `main ()` и отчита получената стойност
и нейния тип. Първата ни програма запазва това изчисление достатъчно малко, за
да го видим като цяло.

Отворете текстов редактор, въведете тези два реда и ги запазете като
`program.ash`:

<!-- source: src/01-literal.ash -->
```ash
main : Unit -> Int
main () = 42
```

Вторият ред дефинира изчислението: дясната му страна е цялото число `42`.
Първият ред е неговата *сигнатура*. Прочетете `Unit -> Int` като „приема стойност
от тип `Unit` и произвежда стойност от тип `Int`“. `Unit`, *unit
типът*, има една стойност, записвана като `()`; `Int` е типът на
целочислените стойности.

Предвидете стойността, която произвежда `main ()`, после стартирайте файла от
терминала си:

```text
ash program.ash
```

Ash отчита:

```text
42 : Int
```

Отчетът потвърждава обещаното от двата реда. Дясната страна на `main` е
*израз*, а изчисляването му произвежда отчетената стойност; сигнатурата задава
типа.

Тъй като `main` получава `()`, не му е нужен вход, за да изчисли
резултата си. [Правилата за начална дефиниция][entry] изискват тя да се
намира във файла, избран за изпълнение.

## Изразите изчисляват стойности

В първия ни израз нямаше нищо за изчисляване: `42` вече е стойност. Един
израз може също да комбинира стойности с операция. Да предположим, че все още
искаме `42`, но искаме да го получим чрез събиране. Променете програмата
така:

<!-- source: src/02-addition.ash -->
```ash
main : Unit -> Int
main () = 40 + 2
```

Дясната страна на `main` вече е изразът `40 + 2`. Преди да стартирате
файла, изчислете стойността му. Същата команда вече отчита:

```text
ash program.ash
42 : Int
```

И двете програми произвеждат една и съща стойност. В първата изразът вече е
`42`. Във втората Ash изчислява събиране, за да получи `42`.

Изразите могат да съдържат по-малки изрази. Помислете какво трябва да се
случи, когато заедно се появят две различни аритметични операции:

<!-- source: src/03-precedence.ash -->
```ash
main : Unit -> Int
main () = 1 + 2 * 3
```

Умножението се групира по-тясно от събирането. Използвайте това правило, за да
предвидите стойността преди стартирането. Ash отчита `7 : Int`; сравнете я със
следните стъпки:

```text
1 + 2 * 3
1 + 6
7
```

По-малкото умножение дава `6`; след това събирането използва тази
стойност, за да получи `7`.

Да предположим, че вместо това искаме първо да се извърши събирането. Скобите
ни позволяват да зададем това групиране в самия израз:

<!-- source: src/04-grouping.ash -->
```ash
main : Unit -> Int
main () = (1 + 2) * 3
```

Променило се е само групирането. Предвидете стойността, после стартирайте
файла. Ash отчита `9 : Int`. Сега изчислението протича така:

```text
(1 + 2) * 3
3 * 3
9
```

Скобите превръщат `1 + 2` в по-малкия израз, който Ash изчислява първо.

> **С учебен асистент:** Стартирайте и двете програми с различното групиране.
> Покажете на асистента предвижданията си, двете програми и действителните
> резултати от `ash`. Обяснете разликата сами, после помолете асистента да
> проверява обяснението ви стъпка по стъпка.

Досега `main` съдържаше цялото изчисление. Дори вложените примери се
побираха на един ред. Когато едно изчисление нарасне, ни трябва начин да
назовем полезна негова част и да я използваме в друг израз.

## Даване на име на изчисление

Следващата програма дава име на изчисление: `increment`. То прибавя единица към
цяло число:

<!-- source: src/05-function-call.ash -->
```ash
increment : Int -> Int
increment number = number + 1

main : Unit -> Int
main () = increment 41
```

Първите два реда принадлежат заедно. Сигнатурата `Int -> Int` казва, че `increment`
приема цяло число и произвежда цяло число. В дефиницията `number` е
*параметър*: той представлява входа, който `increment` получава. Изразът
`number + 1` описва как се изчислява резултатът.

Последният ред използва израза `increment 41`. Това е *извикване на функция*, а
`41` е неговият *аргумент*. За да разберете извикването, използвайте
`41` навсякъде, където дефиницията използва параметъра си. Тази замяна на
параметър с аргумента му се нарича *заместване*. Предвидете резултата преди
стартиране:

```text
ash program.ash
42 : Int
```

Заместването обяснява това наблюдение:

```text
increment 41
41 + 1
42
```

Аргументът заменя параметъра с `41`, затова събирането и външното
`main` дават `42`.

Щом едно изчисление има име, то може да участва в друго изчисление. Добавете
функция, която удвоява цяло число, после използвайте и двете функции в
`main`:

<!-- source: src/06-composition.ash -->
```ash
increment : Int -> Int
increment number = number + 1

double : Int -> Int
double number = number * 2

main : Unit -> Int
main () = double (increment 20)
```

Скобите държат `increment 20` заедно като аргумент на `double`. Започнете с
вътрешното извикване и продължете навън, за да предвидите резултата.
Стартирането на програмата отчита `42 : Int`, както показва проследяването:

```text
double (increment 20)
double 21
21 * 2
42
```

Тук резултатът от `increment` става вход за `double`. Свързването на функции по
този начин се нарича *композиция на функции*.

## Откъде започва изчисляването?

Последният ни изходен файл съдържа три дефиниции, но Ash започва с `main`.
Просто име, което сме избрали случайно, ли е `main`? Можем да разберем,
като дадем друго име на същия вид изчисление:

<!-- source: src/07-missing-main.ash -->
```ash
answer : Unit -> Int
answer () = 42
```

Коя дефиниция в този файл може да осигури необходимото извикване на `main ()`?
Стартирайте запазения пример с `content/learn`, за да проверите това изискване за
начална дефиниция:

<!-- diagnostic: src/07-missing-main.ash -->
<!-- markdownlint-disable MD013 -->
```text
$ ash --message-format human --locale en what-is-an-ash-program/src/07-missing-main.ash
The entry module must define its own `main`; importing one is not enough.
  --> /path/to/ash-doc/content/learn/what-is-an-ash-program/src/07-missing-main.ash:1:1
1 | answer : Unit -> Int
  | ^ This is the entry module.
2 | answer () = 42
  | ^ This is the entry module.
reason: entry.missing-main
```
<!-- markdownlint-enable MD013 -->

Първото изречение назовава липсващото: началният модул трябва да дефинира
собствено `main`. Етикетите на източника обхващат дефиницията `answer` в
този файл и я посочват като начален модул. В тези редове няма нищо с име
`main`. В изречението се споменават и импортите; ще се запознаем с тях в
следващата глава. За тази програма с един файл преименувайте двете срещания на
`answer` на `main`, за да дадете на Ash началната ѝ дефиниция.

Дефиницията на `answer` описва изчисление, но Ash не отгатва коя дефиниция
трябва да стартира програмата. Тя търси `main` и започва с изчисляването на
`main ()`. Затова всяка работеща програма в урока включваше това име.

> след като обясните своето.

## Цялата програма

Сега можем да отговорим на въпроса от заглавието. В най-простия си вид
програмата на Ash е един изходен файл с дефиниции, включително дефиниция с име
`main`, от която започва изчисляването. Дефиницията дава име на изчисление.
Изразът отдясно определя стойността, която то произвежда, а извикванията на
функции позволяват на едно изчисление да използва стойност, произведена от
друго.

Когато стартирате файла, Ash изчислява `main ()` и отчита получената стойност
и тип. Всяка програма тук се побира в един изходен файл, но програмите на Ash
могат да продължат и отвъд него. Следващият въпрос е как може да се използва
дефиниция от един файл в друг.
