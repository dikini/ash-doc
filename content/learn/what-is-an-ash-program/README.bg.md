# Програма на Ash {#an-ash-program}

Обичайно е да мислите за програмата като за списък от команди: направете това,
после направете онова. Изходният файл на Ash има друга форма. Той съдържа
дефиниции. Те описват изрази, а изразите изчисляват стойности.

Една изпълнима програма на Ash се нуждае и от място, откъдето да започне. В
Ash това е дефиниция с име `main`. Когато подадете изходен файл на
`ash`, той изчислява `main ()` и отчита получената стойност и нейния тип.
Първата ни програма прави това изчисление достатъчно малко, за да го видите
цялото.

Отворете текстов редактор, въведете тези два реда и ги запазете като
`program.ash`

<!-- source: src/01-literal.ash -->
```ash
main : Unit -> Int
main () = 42
```

Вторият ред дефинира изчислението: дясната му страна е цялото число `42`.
Първият ред е неговата *сигнатура*. Прочетете `Unit -> Int` като „приема
стойност от тип `Unit` и произвежда стойност от тип `Int`“. `Unit`,
*unit типът*, има една стойност, записвана като `()`; `Int` е типът
на целочислените стойности.

Предскажете стойността, която произвежда `main ()`, после стартирайте файла от
терминала:

```text
ash program.ash
```

Ash отчита:

```text
42 : Int
```

Отчетът потвърждава обещаното от двата реда. Дясната страна на `main` е
*израз*, а изчисляването му произвежда отчетената стойност; сигнатурата задава
типа.

Тъй като `main` получава `()`, преди да изчисли резултата си, не се
нуждае от вход. [Правилата за началната дефиниция][entry] изискват тя да се
намира във файла, избран за изпълнение.

## Изразите изчисляват стойности {#expressions-calculate-values}

В първия ни израз нямаше какво да изчисляваме: `42` вече е стойност.
Изразът може също да комбинира стойности с операция. Да предположим, че все
още искаме `42`, но този път да го получим чрез събиране. Променете
програмата така:

<!-- source: src/02-addition.ash -->
```ash
main : Unit -> Int
main () = 40 + 2
```

Дясната страна на `main` вече е изразът `40 + 2`. Преди да стартирате
файла, пресметнете стойността му. Същата команда вече отчита:

```text
ash program.ash
42 : Int
```

И двете програми произвеждат една и съща стойност. В първата изразът вече е
`42`. Във втората Ash изчислява събиране и така получава `42`.

Изразите могат да съдържат по-малки изрази. Помислете какво трябва да се
случи, когато заедно се появят две различни аритметични операции:

<!-- source: src/03-precedence.ash -->
```ash
main : Unit -> Int
main () = 1 + 2 * 3
```

Умножението се групира по-тясно от събирането. Използвайте това правило, за да
предскажете стойността преди стартирането. Ash отчита `7 : Int`; сравнете я
със следните стъпки:

```text
1 + 2 * 3
1 + 6
7
```

По-малкото умножение произвежда `6`; после събирането използва тази
стойност, за да получи `7`.

Да предположим, че вместо това искаме първо да се извърши събирането. Скобите
ни позволяват да зададем това групиране в самия израз:

<!-- source: src/04-grouping.ash -->
```ash
main : Unit -> Int
main () = (1 + 2) * 3
```

Променило се е само групирането. Предскажете стойността и стартирайте файла.
Ash отчита `9 : Int`. Сега изчислението протича така:

```text
(1 + 2) * 3
3 * 3
9
```

Скобите правят `1 + 2` по-малкия израз, който Ash изчислява първо.

> **С учебен асистент:** Стартирайте и двете програми с различно групиране.
> Покажете асистента на своите предсказания, двете програми и действителните
> резултати от `ash`. Обяснете разликата със свои думи, после помолете
> асистента да поставя обяснението ви под въпрос, стъпка по стъпка.

Досега `main` съдържаше цялото изчисление. Дори вложените примери се
побираха на един ред. Когато изчислението нараства, ни е нужен начин да дадем
име на полезна част и да я използваме в друг израз.

## Даване на име на изчисление {#giving-a-calculation-a-name}

Следващата програма дава име `increment` на изчисление. Тя прибавя едно към
цяло число:

<!-- source: src/05-function-call.ash -->
```ash
increment : Int -> Int
increment number = number + 1

main : Unit -> Int
main () = increment 41
```

Първите два реда са свързани. Сигнатурата `Int -> Int` казва, че `increment`
приема цяло число и произвежда цяло число. В дефиницията `number` е
*параметър*: той обозначава входа, който и да е той, получен от `increment`.
Изразът `number + 1` описва как се изчислява резултатът.

Последният ред използва израза `increment 41`. Това е *извикване на функция*,
а `41` е неговият *аргумент*. За да разберете извикването, използвайте
`41` навсякъде, където дефиницията използва своя параметър. Тази замяна
на параметъра с аргумента се нарича *заместване*. Предскажете резултата преди
стартирането:

```text
ash program.ash
42 : Int
```

Заместването обяснява това наблюдение:

```text
increment 41
41 + 1
42
```

Аргументът замества параметъра със `41`, затова и събирането, и
обхващащото `main` произвеждат `42`.

Щом едно изчисление получи име, то може да участва в друго изчисление.
Добавете функция, която удвоява цяло число, после използвайте двете функции в
`main`:

<!-- source: src/06-composition.ash -->
```ash
increment : Int -> Int
increment number = number + 1

double : Int -> Int
double number = number * 2

main : Unit -> Int
main () = double (increment 20)
```

Скобите държат `increment 20` заедно като аргумент на `double`. Започнете с
това вътрешно извикване и продължете навън, за да предскажете резултата. При
стартиране програмата отчита `42 : Int`, което съвпада с проследяването:

```text
double (increment 20)
double 21
21 * 2
42
```

Тук резултатът от `increment` става вход за `double`. Свързването на функции
по този начин се нарича *композиция на функции*.

## Откъде започва изчисляването? {#where-does-evaluation-begin}

Най-новият ни изходен файл съдържа три дефиниции, но Ash започва с `main`.
Дали `main` е просто име, което случайно сме избрали? Можем да разберем,
като дадем друго име на същия тип изчисление:

<!-- source: src/07-missing-main.ash -->
```ash
answer : Unit -> Int
answer () = 42
```

Коя дефиниция в този файл може да осигури необходимото извикване на `main ()`?
Стартирайте запазения пример от `content/learn`, за да проверите това
изискване за началната дефиниция:

<!-- diagnostic: src/07-missing-main.ash -->
<!-- markdownlint-disable MD013 -->
```text
$ ash --message-format human --locale en what-is-an-ash-program/src/07-missing-main.ash
The entry module must define its own `main`; importing one is not enough.
  --> /path/to/ash-doc/content/learn/what-is-an-ash-program/src/07-missing-main.ash:1:1
1 | answer : Unit -> Int
  | ^ This is the entry module.
2 | answer () = 42
  | ^ This is the entry module.
reason: entry.missing-main
```
<!-- markdownlint-enable MD013 -->

Първото изречение посочва какво липсва: началният модул трябва да дефинира
собствено `main`. Етикетите на източника обхващат дефиницията `answer` в
този файл и я посочват като начален модул. В тези редове няма име `main`. В
изречението се споменават и импорти; ще ги разгледаме в следващата глава. За
тази еднофайлова програма преименувайте и двете срещания на `answer` на
`main`, за да дадете на Ash началната дефиниция.

Дефиницията на `answer` описва изчисление, но Ash не отгатва коя дефиниция
трябва да стартира програмата. Тя търси `main` и започва с изчисляването на
`main ()`. Затова всяка работеща програма в този урок включва това име.

## Цялата програма {#the-whole-program}

Сега вече можем да отговорим на въпроса от заглавието. В най-простия си вид
програмата на Ash е един изходен файл с дефиниции, включително една с име
`main`, откъдето започва изчисляването. Дефиницията дава име на изчисление.
Изразът отдясно определя произвежданата стойност, а извикванията на функции
позволяват на едно изчисление да използва стойност, получена от друго.

Когато стартирате файла, Ash изчислява `main ()` и отчита получената стойност
и тип. Всяка програма тук се побира в един изходен файл, но програмите на Ash
не са ограничени до това. Следващият въпрос е как може да се използва
дефиниция от един файл в друг.
