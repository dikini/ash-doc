# Избор на резултат {#choosing-a-result}

Всяко изчисление в предишните уроци следваше един път. След като започнеше
едно извикване, можехме да го проследим от израз към израз, без да питаме коя
стъпка следва. Понякога обаче една полезна програма трябва да остави
стойността да реши.

Ash взема това решение на две части. Първо един израз дава или `true`, или
`false`. След това един `match` осигурява по един израз за всяка
възможност.

## Задаване на въпрос {#asking-a-question}

Равенството между цели числа пита дали два израза за цели числа дават една и
съща стойност. Резултатът е от тип `Bool`:

<!-- source: src/01-equality.ash -->
```ash
main : Unit -> Bool
main () = 20 + 22 == 42
```

Първо проследете събирането, а после предскажете резултата от равенството.
Стартирайте програмата, за да получите отговора:

```text
true : Bool
```

Събирането подава резултата си за ляв вход на равенството:

```text
20 + 22 == 42
42 == 42
true
```

`Bool` има точно две стойности: `true` и `false`. Променете дясната
страна на равенството на `41` и предскажете резултата, преди отново да
стартирате програмата. Отговорът на въпроса се променя, но типът остава
`Bool`.

Булева стойност може да ни подскаже кой резултат да използваме. Тя не избира
сама; трябва да посочим какво означава всяка от двете ѝ възможни стойности.

## Описване на двата избора {#describing-both-choices}

Следната функция получава условие и два възможни резултата от цели числа:

<!-- source: src/02-choose.ash -->
```ash
choose : Bool -> Int -> Int -> Int
choose condition when_true when_false = match condition {
    true => when_true
    false => when_false
}

main : Unit -> Int
main () = choose true 42 0
```

Прочетете `match` от първия му ред. Той проверява `condition`. Всеки ред във
фигурните скоби е *клон*. Частта преди `=>` назовава възможна форма на
стойността; изразът след `=>` дава резултата за тази форма.

Използвайте подаденото условие, за да изберете клон, после предскажете
стойността, която този клон връща. Стартирайте работната си програма; тя
отчита `42 : Int`. Проследете защо:

```text
choose true 42 0
match true { ... }
42
```

Ако извикването започваше с `choose false 42 0`, щеше да се приложи вторият
клон и резултатът щеше да бъде `0`. И двата клона дават `Int`, което
съвпада с последното `Int` в сигнатурата на `choose`.

`choose` получава входовете си като изчислени стойности. Съпоставянето избира
тялото на един клон, след като получи условието; то не отлага изчисляването на
аргументите на функцията. Изчисляването на аргументите преди изпълнението на
тялото се нарича *стриктно оценяване*. Правилата за [прилагане][application] и
[съпоставяне][evaluation] разграничават тези стъпки.

## Изчисляване на условието {#calculating-the-condition}

Условието не е задължително да бъде написано директно като `true` или
`false`. Всеки израз, който дава `Bool`, може да насочва същото
съпоставяне:

<!-- source: src/03-calculated-choice.ash -->
```ash
choose : Bool -> Int -> Int -> Int
choose condition when_true when_false = match condition {
    true => when_true
    false => when_false
}

main : Unit -> Int
main () = choose (20 + 22 == 42) 42 0
```

Скобите държат равенството заедно като първи вход на `choose`. Първо
предскажете условието, после избрания резултат. Стартирането на програмата
отчита `42 : Int`, което съвпада с проследяването:

```text
choose (20 + 22 == 42) 42 0
choose true 42 0
42
```

Въпросът и изборът са отделни изрази. Така една и съща функция `choose` може
да работи с всяко изчисление, което дава `Bool`.

## Отчитане на всяка стойност {#accounting-for-every-value}

Тъй като `Bool` има две възможни стойности, съпоставянето върху `Bool`
се нуждае от два клона. Разгледайте функция, която отчита само `true`:

<!-- source: src/04-missing-choice.ash -->
```ash
choose : Bool -> Int -> Int
choose condition number = match condition {
    true => number
}

main : Unit -> Int
main () = choose false 42
```

Сравнете възможните стойности на `Bool` с образците в съпоставянето. Кой
вход няма израз за резултат? Стартирайте тази версия от `content/learn`:

Съобщението посочва `false` като вход, който случаите пропускат, и
обозначава непълен `match`. Добавете клон, например `false => 0`, за да
дадете резултат за този вход. Едно *изчерпателно* съпоставяне обхваща всяка
възможна форма на стойността, която проверява. Ash проверява това преди
стартирането на програмата, така че изпълнението не може да стигне до избор
без съответстващ израз.

> **С учебен асистент:** Покажете на асистента непълното съпоставяне и пълната
> диагностика. Попитайте как посочената липсваща стойност се свързва с
> обозначеното съпоставяне. После обяснете защо тази стойност е възможна и кой
> клон би допълнил съпоставянето, преди да поискате обратна връзка.

## Упражнение: запазване или удвояване {#exercise-keep-or-double}

Започнете с чисто копие на `src/02-choose.ash` във вашата работна директория.

Направете врата за едно цяло число. Когато вратата е `true`, числото
преминава непроменено; когато е `false`, числото се удвоява:

```text
keep_or_double : Bool -> Int -> Int
```

Извикайте функцията веднъж с всяка булева стойност, като предскажете и двата
резултата, преди да ги стартирате. После заменете директната булева стойност в
извикването с равенство между цели числа и проверете дали и двата клона все
още дават `Int`, както обещава сигнатурата.

## Пълно решение {#a-complete-decision}

Изборът вече има две части: един израз отговаря на въпроса, а съпоставянето
използва този отговор, като дава на всяка възможна стойност на `Bool`
собствен клон. Ash проверява пълнотата преди стартирането, така че нито едно
извикване не може да стигне до стойност, за която съпоставянето не дава
отговор.

Всеки клон досега съдържаше кратък израз. Когато един път изисква няколко
стъпки, повтарянето на разрастващ се израз става трудно за четене; следващият
урок дава имена на стъпките.
