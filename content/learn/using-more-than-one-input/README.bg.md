# Работа с повече от един вход

Досега функциите ни са получавали по една стойност. `double` е получавала по
едно цяло число; `Arithmetic.answer` е получавала `()`. Много изчисления
изискват повече информация. Например, за да събере две числа, функцията трябва
да получи и двете.

Ash не изисква нов вид извикване за това. Можем да използваме техника,
наречена *къринг* (българска транслитерация на английското *currying*).
Функцията получава първия вход и оставя функция, готова да получи втория.
Подаването на двата входа на един ред е същият процес, записан без пауза.
Можем да видим двете стъпки, като започнем с пълно извикване и после спрем по
средата.

## Подаване на два входа

Ето функция, която събира две цели числа:

<!-- source: src/01-two-inputs.ash -->
```ash
add : Int -> Int -> Int
add left right = left + right

main : Unit -> Int
main () = add 20 22
```

Дефиницията назовава два параметъра: `left` и `right`. При извикването
`add 20 22` входовете съответстват на параметрите отляво надясно. Предскажете
стойността, после запазете и стартирайте програмата. Ash отчита:

```text
42 : Int
```

Заместването обяснява този резултат:

```text
add 20 22
20 + 22
42
```

Сигнатурата разказва същото като дефиницията. Стрелките на функциите [се
групират отдясно][arrows] — стрелката е *дясно асоциативна* — затова четем

```text
Int -> Int -> Int
```

като

```text
Int -> (Int -> Int)
```

Първото `Int` е първият вход. След като този вход пристигне, останалото
има тип `Int -> Int`: функция, която чака втория вход. Когато пристигне
вторият `Int`, изчислението дава крайната `Int`.

## Пауза след първия вход

За да стане видима тази междинна стъпка, премахнете `22` от извикването.
Тъй като `main` вече дава функция, трябва да се промени и типът на
резултата:

<!-- source: src/02-one-input-left.ash -->
```ash
add : Int -> Int -> Int
add left right = left + right

main : Unit -> Int -> Int
main () = add 20
```

Преди да стартирате, пребройте оставащите входове. `add` е получила
`20` за `left`; какво остава да получи `right`, и какъв е типът му?
Стартирайте програмата, за да сравните с предсказанието си:

```text
<function> : Int -> Int
```

Второто цяло число не е пристигнало, затова резултатът е функция от тип
`Int -> Int`. Инструментът показва функцията като `<function>`; това
изображение не показва тялото ѝ. Такова извикване се нарича *частично
извикване* или *частично прилагане*: то подава някои, но не всички входове на
функцията. Резултатът пак е полезен. Той запомня вече подадения вход и може да
получи останалите по-късно.

Три фигури в полето показват визуално същото развитие: сигнатурата спрямо
нейните кутийки, типовете, наложени върху стойностите при пълното извикване, и
проследяването на частичното извикване от `add 20` през `add_20` до
`42`.

Можем да дадем име на чакащата функция и да я използваме на следващия ред:

<!-- source: src/03-reuse-a-partial-call.ash -->
```ash
add : Int -> Int -> Int
add left right = left + right

main : Unit -> Int
main () = {
    let add_20 = add 20
    add_20 22
}
```

Къдравите скоби обединяват тези редове в един *блок*; последният му ред дава
стойността на блока. Свързването `let add_20 = add 20` дава на чакащата
функция името `add_20`. Тя запомня `20` и има тип `Int -> Int`.
Следващият ред подава `22` като оставащ вход. Предскажете резултата,
после стартирайте програмата и сравнете отчета на Ash `42 : Int` с тези
стъпки:

```text
add_20 22
add 20 22
20 + 22
42
```

## Упражнение: умножете три числа

Започнете с ново копие на `src/01-two-inputs.ash` във вашата работна
директория и създайте умножение с три входа и тази сигнатура:

```text
multiply_three : Int -> Int -> Int -> Int
```

След това опитайте три извиквания в `main` едно по едно: подайте всеки вход
и предскажете цялото число; подайте само два и предскажете типа на чакащата
функция; дайте на тази функция последния вход и проверете резултата.
Използвайте стрелките в сигнатурата, за да обясните всеки вход и всеки
резултат.

## От входове към решения

Няколкото входа не променят начина, по който се чете извикването: всяка
стойност пристига отляво, всяка стрелка показва какво остава, а пълното
извикване достига крайния резултат. Частичното извикване просто спира по-рано
и оставя функция, която продължава да чака.

Досега всяко изчисление следваше един фиксиран път. Какво става, когато
програмата трябва да изследва стойност и да избере пътя?
