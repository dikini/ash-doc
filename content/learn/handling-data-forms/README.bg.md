# Обработване на варианти на данни

В предишния урок имаше `Result` два възможни варианта. Можем да конструираме
`Found(42)` или `Missing`, а общият им тип ни казва, че всяка от двете
стойности може да се появи там, където се очаква `Result`. Функция, която
получава такава стойност, трябва да е подготвена и за двата варианта.

Дефиницията на данни направлява функцията. За всеки конструктор в дефиницията
записваме образец със същата форма и израз, който показва какво означава този
вариант за изчислението.

## Съпоставяне с дефиницията на данни

Да предположим, че искаме цялото число, съдържащо се в намерен резултат, а
когато няма цяло число — нула:

<!-- source: src/01-match-result.ash -->
```ash
type Result =
    Found(Int)
    | Missing

value_or_zero : Result -> Int
value_or_zero result = match result {
    Found(value) => value
    Missing => 0
}

main : Unit -> Int
main () = value_or_zero (Found(42))
```

Поставете дефиницията на данни до съпоставянето:

```text
Found(Int)    Found(value) => value
Missing       Missing      => 0
```

Всеки конструктор има съответен клон. Образецът `Found(value)` върши две неща:
разпознава варианта `Found` и дава локално име `value` на полето му с цяло
число. Вариантът `Missing` няма поле, което да именуваме.

Предскажете кой клон обработва `Found(42)`, какво обвързва `value` и какво
връща функцията. Стартирайте я, после сменете извикването с
`value_or_zero Missing` и предскажете резултата, преди да стартирате отново.

Наблюденията са `42 : Int` и `0 : Int`. Образецът `Found` обвързва полето си
с `value`; клонът `Missing` подава собствено цяло число, защото няма поле. И
двата пътя съответстват на типа на резултата в сигнатурата.

## Нека уравненията следват вариантите

Когато функцията започва със съпоставяне на един от входовете си, Ash може да
постави образците направо в отделни уравнения:

<!-- source: src/02-equations.ash -->
```ash
type Result =
    Found(Int)
    | Missing

value_or_zero : Result -> Int
value_or_zero Found(value) = value
value_or_zero Missing = 0

main : Unit -> Int
main () = value_or_zero (Found(42))
```

Сигнатурата все още се отнася за цялата функция. Двете уравнения описват какво
прави функцията за двата варианта на `Result`. Преди да стартирате, намерете
уравнението, избрано за всеки вход, и го сравнете с изричното съпоставяне.
Първото извикване отчита `42 : Int`; двете изчисления са:

```text
value_or_zero Found(42)
42
```

и

```text
value_or_zero Missing
0
```

Тази дефиниция и изричното съпоставяне отговарят на един и същ въпрос.
Използвайте формата, която държи обяснението близо до данните. Отделните
уравнения са полезни, когато цялата дефиниция следва вариантите на входа.

## Следване на всеки клон от дефиницията

Дефиницията на данни служи и като контролен списък. Ако едно уравнение
обработва `Found`, но няма уравнение за `Missing`, функцията е непълна:

<!-- source: src/03-missing-constructor.ash -->
```ash
type Result =
    Found(Int)
    | Missing

value_or_zero : Result -> Int
value_or_zero Found(value) = value

main : Unit -> Int
main () = value_or_zero Missing
```

Сравнете всеки вариант, допустим за `Result`, с уравненията. Кой вариант няма
резултат и дали промяната само на входа на `main` ще изпълни договора на
функцията? Стартирайте тази версия от `content/learn`:

Съобщението назовава `Missing` и посочва непълната дефиниция `value_or_zero`.
Възстановяването на `value_or_zero Missing = 0` дава на този вариант собствен
резултат. Проблемът съществува независимо дали `main` случайно конструира
`Missing`. Сигнатурата приема произволен `Result`, а дефиницията на данни
казва, че `Missing` е такъв. Уравненията трябва да спазват това обещание.

Когато конструкторът носи няколко полета, образецът му трябва да има същия
брой части и същия ред. След това образецът дава локално име на всяка част,
нужна на израза.

## Упражнение: отговор на сигнал

Започнете от ново копие на `src/02-equations.ash` в работната си директория и
се върнете към по-ранната дефиниция:

```text
type Signal =
    Go
    | Stop
```

Добавете отново функция към `Signal`: `signal_value : Signal -> Int`, с по
едно уравнение за всеки конструктор — `Go` дава `1`, а `Stop`
дава `0`. Извикайте функцията с всяка стойност и предскажете двата
резултата.

След това пренапишете уравненията като едно изрично съпоставяне, като запазите
сигнатурата и двете наблюдения. Обяснете как всеки ред от дефиницията на данни
води до едно уравнение и един клон на съпоставянето.

## Функции, които следват данните

Обработването на тип данни изисква по един образец за всеки разрешен вариант:
конструкторът определя варианта, образецът назовава полетата му, а Ash
проверява покритието преди стартиране. Досега данните съдържаха само вече
съществуващи стойности, но дефиницията може да се позовава и на типа, който
дефинира, така че една стойност да води до друга със същата форма. Следващият
урок разглежда това самопозоваване чрез рекурсивна функция.
