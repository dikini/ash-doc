# Дефиниране на локална рекурсия {#defining-local-recursion}

Обикновените локални свързвания разширяват блока стъпка по стъпка. По-късна
функция може да използва по-ранна стойност, но дефиницията обикновено не може
да използва собственото си ново име или име, въведено по-късно. Рекурсивните
функции имат нужда от друга област на видимост: всички имена в групата им
трябва да са достъпни едновременно.

Даването на имена на такава област на видимост поставя и въпрос за
инициализацията. Тялото на функция може да изчака по-късно извикване.
Инициализатор на данни, който веднага се опитва да използва незавършена
стойност, не може да даде същото обещание.

## Започнете от предходната област на видимост {#start-with-the-preceding-scope}

В `01-sequential-bindings.ash`, `add_base` улавя вече свързано цяло число:

<!-- source: src/01-sequential-bindings.ash -->
```ash
main : Unit -> Int
main () = {
    let base = 40
    let add_base = fn(value) {
        base + value
    }
    add_base 2
}
```

`base` е в областта на видимост, докато се проверява анонимната функция.
Разпознайте тази запазена стойност отделно от по-късния аргумент, след което
предскажете сбора им. Стартирайте от директорията `src` на този урок:

```text
$ ash 01-sequential-bindings.ash
42 : Int
```

Новото име `add_base` влиза в областта на видимост след инициализатора си —
същото последователно правило, което всеки урок използва досега.

## Назовете локално рекурсивно изчисление {#name-a-local-recursive-calculation}

`02-local-sum.ash` държи обхождането на списък близо до стойността, която то
използва:

<!-- source: src/02-local-sum.ash -->
```ash
type Scores = End
    | Item(Int, Scores)

main : Unit -> Int
main () = {
    let bonus = 1
    let rec sum : Scores -> Int = fn(values) {
        match values {
            End => 0
            Item(value, rest) => value + bonus + sum rest
        }
    }
    sum (Item(20, Item(20, End)))
}
```

`let rec` прави `sum` достъпно в собствения си инициализатор и в остатъка
от блока. Анотацията му е задължителна: рекурсивните извиквания трябва вече да
имат договор, докато се проверява тялото. Тялото може също да улавя
предходното свързване `bonus`.

Инициализаторът създава функция; той още не изпълнява съпоставянето.
Извикването след групата започва обхождането. Всеки `Item` добавя резултата
си плюс едно, а след това рекурсивното извикване следва `rest`. `End`
добавя нула. Предскажете общия резултат, като различавате уловеното `bonus`
от резултата, подаден с всеки рекурсивен аргумент:

```text
$ ash 02-local-sum.ash
42 : Int
```

Тук завършването следва от крайния вход и преминаването към по-малкия му
остатък. Самата ключова дума `rec` не доказва, че функцията спира.

Рекурсивните анотации задават по един тип за всеки член. Те не въвеждат
локални типови параметри и не прилагат правилото за обобщаване от предходния
урок. Външен типов параметър пак може да се използва там, където вече е в
областта на видимост.

## Поставете взаимно зависими функции в една група {#put-mutually-dependent-functions-in-one-group}

Рекурсивната група може да съдържа няколко члена. Напишете `and` на нов
ред за всеки член след първия:

<!-- source: src/03-mutual-functions.ash -->
```ash
type Count = Zero
    | Next(Count)

main : Unit -> (Bool, Bool)
main () = {
    let rec even : Count -> Bool = fn(count) {
        match count {
            Zero => true
            Next(rest) => odd rest
        }
    }
    and odd : Count -> Bool = fn(count) {
        match count {
            Zero => false
            Next(rest) => even rest
        }
    }
    let two = Next(Next(Zero))
    (even two, odd two)
}
```

`Count` представя неотрицателен брой чрез повтарящи се конструктори
`Next`. `Zero` е четно, а не нечетно. Премахването на едно `Next`
обръща въпроса: четността на цялото изисква нечетност на остатъка, а
нечетността — четност. Дефинициите, които се извикват взаимно по този начин,
са *взаимно рекурсивни*.

Двете имена влизат в областта на видимост, преди да бъде проверен който и да е
инициализатор. И двата инициализатора са анонимни функции, така че
извикванията им към другия член изчакват употребата на функциите. Свързването
`let two` започва обичайния остатък на блока. Предскажете двата резултата,
като редувате извикванията, докато стигнете до `Zero`:

```text
$ ash 03-mutual-functions.ash
(true, false) : (Bool, Bool)
```

Проследете първия резултат като `even two`, след това `odd (Next Zero)`, после
`even Zero`. Второто проследяване завършва на `odd Zero` вместо това. Всяко
извикване все пак следва един по-малък краен брой.

Две последователни свързвания `let` не осигуряват тази взаимна област на
видимост:

<!-- source: src/04-sequential-forward.ash -->
```ash
type Count = Zero
    | Next(Count)

main : Unit -> (Bool, Bool)
main () = {
    let even : Count -> Bool = fn(count) {
        match count {
            Zero => true
            Next(rest) => odd rest
        }
    }
    let odd : Count -> Bool = fn(count) {
        match count {
            Zero => false
            Next(rest) => even rest
        }
    }
    let two = Next(Next(Zero))
    (even two, odd two)
}
```

При инициализатора на `even` кои имена вече са влезли в областта на
видимост? Променя ли отлагането на извикването имената, които тялото му може
да използва?

<!-- diagnostic: src/04-sequential-forward.ash -->
<!-- markdownlint-disable MD013 -->
```text
$ ash --message-format human --locale en 04-sequential-forward.ash
No term named `odd` is in scope.
  --> /path/to/ash-doc/content/learn/defining-local-recursion/src/04-sequential-forward.ash:9:27
9 |             Next(rest) => odd rest
  |                           ^ This name could not be resolved here.
reason: resolve.unknown-name
```
<!-- markdownlint-enable MD013 -->

Етикетът указва `odd`# вътре в по-ранната функция. По-късното свързване не
е в областта на видимост там, дори ако изпълнението би извикало `even` след
двете свързвания. Областта на видимост се определя от изходния текст, а не от
предположение кога ще се изпълни функцията. Възстановете групата `let rec` и
`and` от предходната програма, когато дефинициите зависят една от друга.

## Създайте цикъл, без да го обхождате безкрайно {#build-a-cycle-without-traversing-it-forever}

Рекурсивните групи могат също да свързват именувани данни. Това е различна
употреба на рекурсията от следването на краен списък. `05-guarded-cycle.ash`
дава на всеки възел резултат и следващ възел, без конструктор за край:

<!-- source: src/05-guarded-cycle.ash -->
```ash
type Trail = Step(Int, Trail)

main : Unit -> (Int, Int)
main () = {
    let rec first : Trail = Step(20, second)
    and second : Trail = Step(22, first)
    match first {
        Step(left, rest) => match rest {
            Step(right, ignored) => (left, right)
        }
    }
}
```

Групата запазва двете места за данни, изгражда `Step(20, second)` и
`Step(22, first)` и свързва рекурсивните им препратки. Всеки инициализатор
започва с напълно приложен конструктор от декларирания му именуван тип.
Препратките се съхраняват като полета, вместо съдържанието им да се изчислява
при инициализацията.

Резултатът следва точно два образеца `Step`. Предскажете кой съхранен възел
предоставя всяко върнато цяло число и дали това ограничено наблюдение има
нужда от конструктор за край:

```text
$ ash 05-guarded-cycle.ash
(20, 22) : (Int, Int)
```

След тези два възела следването на следващата връзка би върнало към първия
възел. Цикълът е крайна съхранена структура, но неограниченото обхождане няма
случай за край. Обхожданията на крайни списъци в Learn и Cases разчитат на
достигане до базов конструктор; тук това допускане не важи.

Ограждането с конструктор не е общо *мързеливо оценяване*: Ash не отлага всяко
подизразяване, докато стойността му потрябва. Инициализаторите продължават да
изчисляват обикновените нерекурсивни подизрази. Специалното разрешение е да се
запазват рекурсивни препратки чрез конструктор или кортеж, или да се отлагат в
тялото на анонимна функция. То не прави произволни незавършени стойности
достъпни за изчисление.

## Инициализаторът трябва да задава формата на данните {#the-initializer-must-provide-its-data-shape}

Гола препратка към самото име не конструира възел:

<!-- source: src/06-unsafe-root.ash -->
```ash
type Trail = Step(Int, Trail)

main : Unit -> Int
main () = {
    let rec trail : Trail = trail
    0
}
```

Сравнете външната форма на този инициализатор с изискването стойността да
започва с конструктор. Какъв възел би конструирал, преди да се опита да запази
собствената си препратка?

<!-- diagnostic: src/06-unsafe-root.ash -->
<!-- markdownlint-disable MD013 -->

Съобщението посочва инициализатора, рекурсивната му група и декларирания му
именуван тип. Няма стойност, започваща с конструктор, която да инициализира.
Напишете `Step(42, trail)`, за да изградите възел, който запазва собствената
си препратка, или използвайте обикновено нерекурсивно свързване, когато не е
нужен цикъл. Неизползваният резултат от групата не прави небезопасната
инициализация приемлива.

Необходим е корен-конструктор, но препратките под него също трябва да са
защитени:

<!-- source: src/07-forced-reference.ash -->
```ash
type Trail = Step(Int, Trail)

keep : Trail -> Trail
keep value = value

main : Unit -> Int
main () = {
    let rec trail : Trail = Step(42, keep trail)
    0
}
```

Външният конструктор е налице. Проследете рекурсивната поява под него:
съхранява ли се препратката директно, или се подава през изчисление, което
проверката на инициализацията не разрешава?

<!-- diagnostic: src/07-forced-reference.ash -->
<!-- markdownlint-disable MD013 -->
```text
$ ash --message-format human --locale en 07-forced-reference.ash
This recursive value cannot be passed through this expression during initialization.
  --> /path/to/ash-doc/content/learn/defining-local-recursion/src/07-forced-reference.ash:8:38
8 |     let rec trail : Trail = Step(42, keep trail)
  |                                      ^ This recursive value cannot be passed through this expression during initialization.
reason: recursion.unguarded-use
```
<!-- markdownlint-enable MD013 -->

`keep` е обикновено извикване. Подаването на незавършеното `trail` през
него преминава през форма, която проверката на инициализацията не допуска.
Връщането на аргумента без промяна не превръща извикването в конструктор.
Заменете `keep trail` с директното поле `trail`, за да запазите препратката,
без да извиквате функция върху нея.

[Правилата за рекурсивните групи][groups] определят и двете проверки;
[правилата за изпълнение][execution] обясняват запазването и инициализирането
на рекурсивните места за данни. Нито едно от правилата не разрешава произволни
рекурсивни цели числа, неявно отлагане или обещание, че по-късните обхождания
ще завършат.

## Упражнение: отделете конструирането от употребата {#practice-separate-construction-from-use}

За всяка задача направете ново копие на посочената програма в работна
директория извън дървото `src` на този урок. Стартирайте копието от тази
директория.

1. Променете `bonus` и входния списък в `02-local-sum.ash`. Проследете кои
   стойности идват от улавянето и кои — от всеки рекурсивен аргумент.
2. Добавете едно `Next` към `two` в `03-mutual-functions.ash`.
   Предскажете двата резултата, като проследите редуващите се извиквания,
   преди да стартирате.
3. Започнете от `03-mutual-functions.ash` и разменете декларациите на двата му
   члена. Оставете `let rec` при първия и `and` при втория. Обяснете дали
   областта на видимост се променя.
4. Разширете `05-guarded-cycle.ash`, така че да наблюдавате точно три
   резултата. Предскажете кой възел предоставя третия и запазете фиксирана
   граница на наблюдението.

Рекурсивната група дава на имената си обща област на видимост, с изрични
договори и безопасна инициализация: функциите отлагат телата си до извикване,
а полетата на конструктора могат да запазват защитени връзки. Това, което се
случва след инициализацията, продължава да зависи от извикванията и данните в
програмата. Като разберете тази граница, можете да надградите върху локални
функции по пътищата [effects](../../effects/README.md) и
[library](../../libraries/README.md), без да приемате, че всички те са
полиморфни или че всяка рекурсивна структура е краен списък.
