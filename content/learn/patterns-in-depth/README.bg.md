# Образци в подробности

В предишния урок за всеки конструктор на тип данни имаше отделно уравнение и
всеки образец назоваваше всяко поле, което конструкторът съдържа. Реалните
функции рядко са толкова подробни. При отчет за точките, получени за оценен
отговор, няма нужда от възможните точки, а функция, която запазва първото цяло
число от двойка, никога не проверява второто. В този урок ще разширите речника
от образци за такива функции: ще пропускате поле, без да го назовавате, ще
проследявате стойност два слоя навътре, ще изграждате образец от самите малки
стойности и ще посочвате тип до образец.

## Назоваване на полето, което е нужно на изчислението

Оцененият отговор съдържа две цели числа: получените точки и възможните точки;
празният отговор не съдържа нищо:

<!-- source: src/01-earned-points.ash -->
```ash
type Answer =
    Marked(Int, Int)
    | Blank

earned_points : Answer -> Int
earned_points Marked(earned, _) = earned
earned_points Blank = 0

main : Unit -> Int
main () = earned_points (Marked(42, 50))
```

Уравнението `Marked` назовава първото си поле с `earned`, а за второто
записва `_`. Предскажете резултата за показания оценен отговор, след
което стартирайте програмата; Ash отчита `42 : Int`.

Сега променете извикването на `earned_points (Marked(42, 60))` и предскажете
отново. Второто поле се промени, а резултатът остана същият; Ash отново отчита
`42 : Int`. Образецът `_` се нарича заместващ знак: той съпоставя всяка
стойност, която заема полето, и не свързва име с нея, така че едно уравнение
служи за всяко възможно второ поле. Уравнението `Blank` не назовава поле,
защото конструкторът му не съдържа такова.

## Пропускането на поле не означава пропускане на случай

Заместващият знак отговаря на въпрос за полетата. Той не отговаря на другия
въпрос, на който функцията трябва да отговори: за кои конструктори има
уравнения. Премахнете уравнението `Blank`:

<!-- source: src/02-missing-case.ash -->
```ash
type Answer =
    Marked(Int, Int)
    | Blank

earned_points : Answer -> Int
earned_points Marked(earned, _) = earned

main : Unit -> Int
main () = earned_points (Marked(42, 50))
```

Всяко поле на `Marked` е назовано, така че оставащото уравнение изглежда
пълно. Сравнете образците му с дефиницията на данните: за кой конструктор няма
резултат? Стартирайте тази версия от `content/learn`:


Съобщението назовава `Blank` и обозначава непълната дефиниция

конструктор, а проверката на покритието продължава да изисква уравнение за
всеки конструктор. Като възстановите `earned_points Blank = 0`, ще дадете на
тази форма собствен резултат.

> **С учебен асистент:** Покажете на асистента едното уравнение и пълната

> кой етикет обозначава дефиницията. После, преди да поискате обратна връзка,
> обяснете защо пропускането на поле в `Marked` никога не би могло да покрие
> `Blank`.

## Проследяване на стойност два слоя навътре

Поле в един тип може да съдържа стойност от друг тип данни. Един запис е или
оценен отговор, или пропуск:

<!-- source: src/03-two-layers.ash -->
```ash
type Answer =
    Marked(Int, Int)
    | Blank

type Entry =
    Graded(Answer)
    | Skipped

earned_from : Entry -> Int
earned_from Graded(Marked(earned, _)) = earned
earned_from Graded(Blank) = 0
earned_from Skipped = 0

main : Unit -> Int
main () = earned_from (Graded(Marked(42, 50)))
```

Първият образец преминава през двата слоя: `Graded(Marked(earned, _))` се
прилага само когато записът съдържа оценен, отбелязан отговор, а след това
`earned` назовава първото поле на този отговор. Възможните точки остават
неназовани, а другите две уравнения запазват формата си. Предскажете резултата
за показания оценен отговор, след което сменете входа на `main` със
`Graded(Blank)` и с `Skipped`, като предскажете резултата при всеки случай,
преди да стартирате. При първото извикване се отчита `42 : Int`, а при другите
две — `0 : Int`.

Записването на двата слоя в един образец държи формата на уравнението до
формата на стойността. Две съпоставяния, по едно за всеки слой, биха задали
същия въпрос с повече механизми.

## Образци, изградени от самите стойности

`Bool` има две стойности и всяка може да стои директно в уравнение.
Функцията `choose` от четвъртия урок съпоставяше условието си; същата функция
може да се запише като две уравнения:

<!-- source: src/04-boolean-equations.ash -->
```ash
pick : Bool -> Int -> Int -> Int
pick true when_true when_false = when_true
pick false when_true when_false = when_false

main : Unit -> Int
main () = pick (20 + 22 == 42) 42 0
```

Буквалните образци `true` и `false` избират уравнение според стойността
на условието. Покритието се проверява за тях както за всички други образци:
ако пропуснете второто уравнение, съобщението посочва `false` като непокрит
вход. Стойността unit също има буквален образец и участва във всяка програма
досега — `main ()` е уравнение, чийто образец е `()`. Предскажете кое
уравнение ще избере показаното извикване, след което го стартирайте; Ash
отчита `42 : Int`.

## Посочване на типа до образеца

Образецът може да посочва типа, на който трябва да съответства. В локално
свързване запишете типа след образеца:

<!-- source: src/05-checked-binding.ash -->
```ash
main : Unit -> Int
main () = {
    let (low, high) : (Int, Int) = (20, 22)
    high
}
```

Ash проверява образеца спрямо посочения тип — тук `(low, high)` спрямо
`(Int, Int)` — и проверява инициализатора спрямо него, така че
несъответствието води до грешка в типа, отчетена преди стартирането на
програмата. При стартиране на програмата се отчита `22 : Int`.

## Упражнение: пребройте целите числа

Започнете с ново копие на `src/01-earned-points.ash` в работната си директория
и заменете дефиницията в програмата със следната:

```text
type Roll =
    Both(Int, Int)
    | One(Int)
    | None
```

Дефинирайте `count : Roll -> Int`, която брои целите числа в едно хвърляне:
`Both` съдържа две, `One` съдържа едно, а `None` не съдържа нито
едно. Броят не зависи от самите цели числа, затова използвайте заместващия
знак, за да оставите всяко поле неназовано. Извикайте `count` с всяка форма
на `Roll` и предскажете трите резултата, преди да стартирате програмата.

След това дефинирайте `add_up : Roll -> Int`, която събира всяко цяло число в
едно хвърляне. Назовете само полетата, нужни за събирането. Сравнете двете
дефиниции: кои уравнения промениха формата си и кои останаха същите?

## Какво може да изрази един образец

Във всички тези програми се повтаря една идея: образецът описва формата на
стойността, с която се съпоставя. Заместващият знак заема поле, без да го
назовава. Вложен образец проследява слоевете на стойността. Буквалните образци
позволяват стойностите `Bool` и `Unit` сами да изберат уравнението.
Посоченият тип дава основание образецът да бъде проверен. А проверката на
покритието пита за всеки образец кои стойности все още нямат уравнение.

Досега всяка стойност имаше ограничена форма — един отговор, един запис, едно
хвърляне. Дефиницията на данни може обаче да посочва типа, който дефинира,
така че една стойност да съдържа друга със същата форма. Следващият урок
разглежда това самопосочване.
